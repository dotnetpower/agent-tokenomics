효과 등급은 측정된 절감액이 아니라 우선순위를 정하기 위한 정성적 기준입니다. 플랜과 작업에 따라 달라지므로 기준선과 비교해 비용과 품질을 확인하세요.

## 세션을 시작하기 전에

- [ ] [효과: 상] 새 작업이면 새 채팅을 시작합니다. 별도 질문에는 `/fork`를 사용합니다.
- [ ] [효과: 상] 이 작업에 필요한 도구와 MCP 서버만 활성화했습니다.
- [ ] [효과: 상] 모델을 의도적으로 선택했습니다(기본은 자동). 추론 강도는 기본값으로 두었습니다.
- [ ] [효과: 중] 노이즈가 많은 경로를 제외했습니다(`.gitignore`, `files.exclude`, `search.exclude`).
- [ ] [효과: 상] 프롬프트에 파일, 오류, 제약 조건, 성공 기준을 명시했습니다.
- [ ] [효과: 중] 프롬프트 끝에 출력 제한(`Code only.` / `3 bullets max.`)을 붙였고, 프롬프트 하나에는 작업 하나만 담았습니다.
- [ ] [효과: 중] 상시 지침과 규칙은 영어로, 간결하게, 중복 없이 작성했습니다.

## 작업 중

- [ ] [효과: 중] 알고 있는 파일에는 #-멘션을 사용합니다. `#codebase`는 검색이 필요할 때만 사용합니다.
- [ ] [효과: 상] 복잡한 변경은 먼저 계획하고 구현합니다. 범위가 정해진 작업은 더 저렴한 서브에이전트에 위임합니다.
- [ ] [효과: 상] 모호한 작업은 Agent를 실행하기 전에 Ask 또는 Plan으로 범위를 정하고, 명확한 완료 기준을 제시합니다.
- [ ] [효과: 상] 세션이 길어졌지만 계속 필요하면 `/compact`를 실행할 때 요약의 초점을 지정합니다.
- [ ] [효과: 중] 대량 작업이나 폴링 작업은 스크립트로 실행하고, 모델에는 요약만 전달합니다.

## 주간 검토

- [ ] [효과: 하] Copilot 상태 대시보드를 엽니다. 월간 허용량을 얼마나 사용했나요?
- [ ] [효과: 중] 비용이 가장 컸던 세션 세 개를 찾아 원인을 확인합니다(컨텍스트 윈도우 팝오버).
- [ ] [효과: 하] 사용할 수 있으면 `/chronicle:cost-tips`를 실행하고, 없으면 Agent Debug Logs의 Summary와 Cache Explorer를 확인합니다.
- [ ] [효과: 상] 필요하지 않았던 지침과 도구를 가지치기합니다([MCP 감사](../09-mcp-audit/)).

## 판단이 서지 않을 때

[2페이지에서 사용량을 측정](../02-measure-usage/)하고 한 가지만 바꾼 뒤 다시 측정합니다. 품질이 유지된 경우에만 변경을 유지합니다.
